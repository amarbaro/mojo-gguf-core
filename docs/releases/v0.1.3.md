## What it does

<!-- Stable description of the program. Carried forward from the previous note; edit only when the product itself changes.

Read and write GGUF model files from Mojo: an mmapped zero-copy reader and a writer with gguf-py's bytes.

## Highlights

- A corrupt or hostile GGUF raises an error instead of crashing the reader or walking memory: negative string,
  array and offset lengths, tensor sizes that overflow, and arrays nested deeper than 32 are refused.
- Opening a file is faster: 11 ms instead of 18 ms (median of 11 runs) on a 4.3 MB stand-in with a 248k-token
  vocabulary and 733 tensors.

## Changes

### Added
- `recipe.yaml`: the conda package `mojo-gguf-core`.
### Changed
- The reader allocates nothing per value type or skipped string, and checks duplicate keys and tensor names with a
  hash table instead of comparing every pair.
- README: one example and one install block.
### Fixed
- A string length, array count or tensor offset of 2^63 or more is refused (an array count wrapped negative and
  crashed the reader).
- Tensor dimensions whose product overflows are refused (`[2^32, 2^32]` used to give 0 bytes and pass).
- Arrays nested more than 32 deep raise `arrays nested more than 32 deep`.
- `pyproject.toml` carries the release version.

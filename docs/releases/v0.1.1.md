# mojo-gguf-core v0.1.1

**Released:** 2026-10-21 · **Commit:** the one tagged v0.1.1 · **Previous:** v0.1.0

## What it does

Fixes a build failure next to `FileHandle.seek()`, and can open GGUFs whose tensors use fork-only ggml types.

## Highlights

- The file size now comes from glibc `lseek64`. The standard library declares `lseek` itself with another signature, and Mojo refuses two signatures for one symbol ("existing function with conflicting signature").
- New `tests/coexist.mojo`, run by `scripts/check.sh`: seeks a file and opens one with the library. It fails on v0.1.0 and passes now.

## Changes

- feat: `Gguf(path, known_types=False)` opens files with ggml types it does not know (fork types such as PQ2_0); default unchanged
- fix: `lseek64` instead of `lseek` (found moving iTools gguf-experts onto the library)
- test: `tests/coexist.mojo` in the gate
